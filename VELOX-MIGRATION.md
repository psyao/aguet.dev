# Moving aguet.dev onto Velox

The friction log of moving this Site onto [Velox](https://github.com/psyao/velox), tracked by Velox's map "Map: aguet.dev on Velox, in production" (psyao/velox#309). Each friction is numbered in the order found: the step (the map's ticket), what happened, the workaround, and the verdict. A friction that is a Velox gap also gets a ticket in Velox.

## Steps

## Friction log

| # | Step | What happened | Workaround | Verdict |
| --- | --- | --- | --- | --- |
| 1 | 1 | The visual suite fails 9 of 13 snapshots (home FR/EN desktop and mobile, contact modal ×4, command palette), on `main` as on the update: its baselines were taken on macOS 15.7.5 with Chromium v1223/v1228, this machine now runs macOS 26.6 with Chromium v1243 | None: the failures predate the update | Closed in step 2: baselines regenerated on macOS 26.6 with Chromium v1248 |
| 2 | 1 | Playwright 1.64 needs Chromium v1248, not installed here; a newer Chromium also re-renders the snapshots | Playwright kept at 1.61.1 | Closed in step 2: Playwright 1.64.1 and its Chromium installed |
| 3 | 4 | `velox:install` rewrites `bootstrap/providers.php` although `AdminPanelProvider` is already listed: Laravel's `addProviderToBootstrapFile()` drops the file's `use` imports and writes fully qualified class names | File restored from `main` | Velox gap: only add the provider when the bootstrap file doesn't list it (psyao/velox#338). Closed in step 5: fixed in Velox 0.24.0 |
| 4 | 4 | `velox:install` makes `User` an Account, but the model's own `canAccessPanel()` (returning `true`) wins over `IsAccount`'s, so the Admin stays open to every user, Role or not; the edit also leaves `implements Account, FilamentUser` and unsorted imports | `canAccessPanel()`, `FilamentUser` and its imports removed by hand; a test proves a user without a Role gets a 403 | Velox gap, security-relevant: `velox:install` should warn (or stop) when the user model defines its own `canAccessPanel()`, and drop the redundant `FilamentUser` (psyao/velox#336). | 5 | 4 | Velox's `{path}` catch-all is registered once the app has booted, so a route added later (aguet's error page tests register throwing routes at runtime) is shadowed by it; and every unknown path now looks itself up in `velox_entries`, so those tests need the database | The error page tests mark `velox.entry` as a fallback route in `beforeEach` and use `RefreshDatabase` | Velox gap: register the catch-all with `->fallback()` so any Site route wins, whenever registered (psyao/velox#337); the database lookup per unknown path is by design. Closed in step 5: fixed in Velox 0.24.0, the tests' `fallback()` line gone |
| 6 | 4 | `role` isn't mass assignable, so the seeder's `updateOrCreate()` silently dropped it and the seeded admin had no Role; `User::factory()` users had none either, so every existing Admin test was refused the panel | The seeder `forceFill()`s `role = developer`; the factory's users default to Developer (every aguet user is one) | Accepted; Velox docs note in `accounts.md` (psyao/velox#339): an existing Site's seeders and factories must set `role`. Closed in step 5: documented in Velox 0.24.0 |
| 7 | 5 | Re-running `velox:install` on a trimmed Site writes back everything trimmed: `app/ContentTypes/Page.php` and `Post.php` (warning to list them in `config/velox.php`), `app/Taxonomies/Category.php` and every `resources/views/velox` view, since it only asks before overwriting a file that exists | The files deleted again | Velox gap: a re-run should only add what a Site never had, or let a Site opt out of the starter content (psyao/velox#341). Closed in step 8: fixed on Velox's `main` (3695fe6) and tried on the playground (section 38); not re-run on aguet yet |
| 8 | 6 | Velox serves `/` and `/en` from its own `velox.entry` route in the `web` group, so the CSP middleware that wrapped aguet's page routes has nowhere to attach: appended to `web`, it would also reach the Admin, whose asset origins it doesn't allow | `SetSecurityHeaders` appended to the `web` group, returning early unless the route is `velox.entry` or `velox.preview` (a Preview takes the Public page's headers) | Accepted, no Velox code change: the route names are public surface.
