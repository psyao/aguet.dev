# Moving aguet.dev onto Velox

The friction log of moving this Site onto [Velox](https://github.com/psyao/velox), tracked by Velox's map "Map: aguet.dev on Velox, in production" (psyao/velox#309). Each friction is numbered in the order found: the step (the map's ticket), what happened, the workaround, and the verdict. A friction that is a Velox gap also gets a ticket in Velox.

## Steps

| Step | Ticket | Outcome |
| --- | --- | --- |
| 1 | Update aguet's PHP and JS dependencies to Velox's floors (psyao/velox#310) | Laravel 13.19 → 13.37, Filament 5.7.0-beta2 → 5.10.2 (stable, `minimum-stability` back to `stable`), Pest 4 → 5, PHPUnit 12 → 13, Guzzle 7 → 8 (through Laravel), Boost 2.4 → 2.10 and its skills reinstalled; Vite 8.3, Tailwind 4.3.3, laravel-vite-plugin 3.2; Node 26 in `.nvmrc` and `.node-version` (CI reads the latter). 149 tests pass; the visual suite fails as on `main` (friction 1) |
| 2 | Regenerate aguet's visual baselines on today's macOS and Chromium (psyao/velox#319) | Playwright 1.61.1 → 1.64.1 (Chromium v1248); the 9 failing baselines regenerated on macOS 26.6 after eyeballing every diff: text anti-aliasing only, plus the EN mobile contact modal no longer captured with the viewport scrolled 11px sideways. 11 of 13 pass, 2 skipped (print), stable over two runs |
| 3 | Add a French 404 visual baseline on aguet's main (psyao/velox#335) | `ErrorPageVisualTest` captures `/this-route-does-not-exist` in French (desktop) on macOS 26.6, Playwright 1.64.1, Chromium v1248; the 10 baselines pass, 12 of 14 tests (2 skipped, print), stable over two runs; no friction |
| 4 | Install Velox on aguet's velox branch, the User as the Developer Account (psyao/velox#326) | On the `velox` branch: `psyao/velox` required as `^0.23` through a symlinked Composer `path` repository to `~/Code/velox` (pinned to 0.23.0 by the repository's `versions` option), which brings intervention/image 4, solution-forest/filament-tree 4.0.2 and Carbon 3.14.2 → 3.15.0. `velox:install --no-interaction` run, then trimmed: Page, Post, Category, the Menus and every `resources/views/velox` view go, aguet's own `errors/404` kept (not overwritten), `Tag` kept inert (no Content Type lists it yet) for the content model ticket. Locales `fr` (default) and `en`. The panel keeps its login, brand, Emerald colour, navigation groups and the translatable-fields plugin for the old Resources, and registers `VeloxPlugin`. `User` is a Velox Account, its own panel gate gone; the seeder's admin and the factory's users are Developers. 153 tests pass (4 new: seeded admin signs in, is a Developer, reaches the SEO settings and Accounts; a user without a Role is refused); the visual suite passes as on `main`, 12 of 14 (2 skipped, print) |
| 5 | Fix frictions 3 to 6 in Velox and move aguet to 0.24 (psyao/velox#336, #337, #338, #339) | The four fixes landed on Velox's `main` (90786a7, 3ac9077, 41d7b37, 396de80), released as 0.24.0 by psyao/velox#340, a `feat!` (a Site can no longer declare its own `Route::fallback()`; aguet declares none), so aguet now requires `^0.24` instead of the spec's `^0.23`. aguet drops the error page tests' `fallback()` line (they keep `RefreshDatabase`), and ignores `public/{css,js}/psyao`, the tree assets Velox 0.24 publishes. Re-running `velox:install` leaves `bootstrap/providers.php` untouched and doesn't warn on aguet's User, which has no `canAccessPanel()` of its own any more. 153 tests pass; the visual suite passes as on `main`, 12 of 14 (2 skipped, print) |

## Friction log

| # | Step | What happened | Workaround | Verdict |
| --- | --- | --- | --- | --- |
| 1 | 1 | The visual suite fails 9 of 13 snapshots (home FR/EN desktop and mobile, contact modal ×4, command palette), on `main` as on the update: its baselines were taken on macOS 15.7.5 with Chromium v1223/v1228, this machine now runs macOS 26.6 with Chromium v1243 | None: the failures predate the update | Closed in step 2: baselines regenerated on macOS 26.6 with Chromium v1248 |
| 2 | 1 | Playwright 1.64 needs Chromium v1248, not installed here; a newer Chromium also re-renders the snapshots | Playwright kept at 1.61.1 | Closed in step 2: Playwright 1.64.1 and its Chromium installed |
| 3 | 4 | `velox:install` rewrites `bootstrap/providers.php` although `AdminPanelProvider` is already listed: Laravel's `addProviderToBootstrapFile()` drops the file's `use` imports and writes fully qualified class names | File restored from `main` | Velox gap: only add the provider when the bootstrap file doesn't list it (psyao/velox#338). Closed in step 5: fixed in Velox 0.24.0 |
| 4 | 4 | `velox:install` makes `User` an Account, but the model's own `canAccessPanel()` (returning `true`) wins over `IsAccount`'s, so the Admin stays open to every user, Role or not; the edit also leaves `implements Account, FilamentUser` and unsorted imports | `canAccessPanel()`, `FilamentUser` and its imports removed by hand; a test proves a user without a Role gets a 403 | Velox gap, security-relevant: `velox:install` should warn (or stop) when the user model defines its own `canAccessPanel()`, and drop the redundant `FilamentUser` (psyao/velox#336). Closed in step 5: fixed in Velox 0.24.0 |
| 5 | 4 | Velox's `{path}` catch-all is registered once the app has booted, so a route added later (aguet's error page tests register throwing routes at runtime) is shadowed by it; and every unknown path now looks itself up in `velox_entries`, so those tests need the database | The error page tests mark `velox.entry` as a fallback route in `beforeEach` and use `RefreshDatabase` | Velox gap: register the catch-all with `->fallback()` so any Site route wins, whenever registered (psyao/velox#337); the database lookup per unknown path is by design. Closed in step 5: fixed in Velox 0.24.0, the tests' `fallback()` line gone |
| 6 | 4 | `role` isn't mass assignable, so the seeder's `updateOrCreate()` silently dropped it and the seeded admin had no Role; `User::factory()` users had none either, so every existing Admin test was refused the panel | The seeder `forceFill()`s `role = developer`; the factory's users default to Developer (every aguet user is one) | Accepted; Velox docs note in `accounts.md` (psyao/velox#339): an existing Site's seeders and factories must set `role`. Closed in step 5: documented in Velox 0.24.0 |
| 7 | 5 | Re-running `velox:install` on a trimmed Site writes back everything trimmed: `app/ContentTypes/Page.php` and `Post.php` (warning to list them in `config/velox.php`), `app/Taxonomies/Category.php` and every `resources/views/velox` view, since it only asks before overwriting a file that exists | The files deleted again | Velox gap: a re-run should only add what a Site never had, or let a Site opt out of the starter content (candidate Velox ticket, not filed) |
